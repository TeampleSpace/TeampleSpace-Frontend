# 파일 출력 비교 기록

백엔드가 만드는 PPTX, PDF 파일을 화면과 비교하기 위한 기준과 결과를 남기는 문서다. PPTX는 PowerPoint에서 편집하는 파일이고 PDF는 페이지 모양을 고정한 파일이다. 사용자용 내려받기 기능은 이 문서의 범위가 아니다.

## 기준 화면

- 주소는 개발 서버의 `/dev/reference`다. 운영 빌드에는 포함되지 않는다
- 백엔드의 파일 출력 실험과 같은 예제 문서 `contracts/examples/presentation.json`을 편집 장식 없이 문서 좌표 그대로 100%로 그린다
- 캔버스는 1280 x 720 px이고 슬라이드는 두 장이다
- 주소 뒤에 `?slide=1`처럼 번호를 붙이면 그 슬라이드만 화면 왼쪽 위에 그린다. 화면 캡처에 쓴다
- 화면 아래 표에 요소별 좌표, 크기, 회전, 스타일, 내용, 출처가 나온다

## 기준 이미지

| 파일 | 내용 |
| --- | --- |
| `docs/reference/slide-1.png` | 첫째 슬라이드. 제목 띠, 흰색 제목, 줄바꿈이 있는 본문, 작성 정보 |
| `docs/reference/slide-2.png` | 둘째 슬라이드. 긴 본문, 줄바꿈 목록, 둥근 사각형, 자른 이미지, 타원, 회전한 글자, 출처 |

2026-11-18에 macOS의 Chrome으로 창 크기 1280 x 720, 배율 1로 캡처했다. 이 환경에는 Pretendard가 설치되어 있어 문서에 적힌 글꼴로 그려졌다. 글꼴이 없는 환경에서는 대체 글꼴로 그려져 줄바꿈 위치가 달라질 수 있고, 기준 화면의 글꼴 항목이 이를 알려 준다.

기준 이미지를 다시 만들 때는 개발 서버를 켠 뒤 아래처럼 실행한다.

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --hide-scrollbars --force-device-scale-factor=1 --window-size=1280,720 --screenshot=docs/reference/slide-2.png "http://localhost:5173/dev/reference?slide=2"
```

## 기준 화면의 줄바꿈 위치

2026-11-18에 기준 화면에서 잰 값이다. 슬라이드 글상자는 글자 단위로 줄을 바꾼다.

둘째 슬라이드의 긴 본문은 네 줄로 나뉜다.

```text
설문에 참여한 대학생 가운데 다수는 발표 자료를 만들 때 각자 작업한 내
용을 마지막에 한꺼번에 합치는 과정에서 가장 많은 시간을 쓴다고 답했
으며, 누가 어떤 부분을 고쳤는지 확인하기 어렵다는 점을 두 번째 어려움
으로 꼽았습니다.
```

직접 넣은 줄바꿈은 그대로 줄을 나눈다. 첫째 슬라이드의 본문은 두 줄, 둘째 슬라이드의 핵심 정리는 네 줄이다. 나머지 글상자는 한 줄이다.

## 비교 방법

- PDF는 각 페이지를 1280 x 720 이미지로 바꿔 기준 이미지와 나란히 놓거나 겹쳐서 본다
- PPTX는 PowerPoint에서 열어 같은 크기로 보고, 글상자와 도형을 선택해 편집할 수 있는지와 위치, 크기를 확인한다
- 숫자로 확인할 값은 기준 화면 아래의 요소 표와 비교한다

## 비교할 항목

| 항목 | 볼 것 |
| --- | --- |
| 한글 글꼴 | 문서에 적힌 글꼴로 나오는지, 대체 글꼴로 바뀌었는지 |
| 긴 문장의 줄바꿈 | 위 줄바꿈 위치와 같은지. PowerPoint는 한글 줄바꿈 설정에 따라 달라질 수 있음 |
| 직접 넣은 줄바꿈 | 그대로 줄을 나누는지 |
| 글자 모양 | 크기, 굵기, 색, 정렬, 줄 간격 |
| 도형 | 위치, 크기, 채움 색, 선 색과 두께, 둥근 모서리, 타원 |
| 이미지 | 위치와 크기, 가장자리 5%를 자른 영역, 가로세로 비율 |
| 회전 | 가운데를 기준으로 같은 각도로 도는지 |
| 겹침 순서 | 둥근 사각형 위에 이미지가 올라가는지 |
| 출처 | 출처 문구가 보이는지, 출처 연결 정보가 합의된 방식으로 표시되는지 |
| 슬라이드 | 순서와 크기 |

## 비교 결과

2026-11-18에 백엔드 출력 실험의 결과와 기준 이미지를 비교했다. 백엔드 저장소 `main`의 `experiments/export/output`에 있는 파일을 썼고, 그 실험은 같은 예제 문서로 PDF와 PPTX를 만든 것이다.

| 비교한 것 | 백엔드 파일 | 방법 |
| --- | --- | --- |
| 기준 화면과 PDF | `pdf-page-1.png`, `pdf-page-2.png` | 1280 x 720 이미지끼리 픽셀 차이를 영역별로 계산. 둘째 슬라이드는 눈으로도 나란히 봄 |
| 기준 화면과 PowerPoint | `powerpoint-page-1.png`, `powerpoint-page-2.png` | 같은 방법. PowerPoint 16.113.3이 PPTX를 열어 내보낸 PDF를 그린 그림이다 |

### 같은 것

- 사각형, 둥근 사각형, 타원, 이미지와 자른 영역의 위치와 크기가 세 결과에서 같다. 둘째 슬라이드의 그림 영역에서 기준 화면과 다른 픽셀은 PDF와 PowerPoint 모두 0.9%이고 첫째 슬라이드는 0.1% 이하다
- 회전한 글자가 같은 자리에서 같은 방향으로 기울어 있다
- 직접 넣은 줄바꿈은 세 결과 모두 그대로 줄을 나눈다
- 출처 문구가 같은 자리에 보인다
- 슬라이드 순서와 크기가 같다

### 다른 것

숨기지 않고 그대로 적는다. 이후 내보내기 단계에서 다뤄야 할 제한이다.

| 항목 | 기준 화면 | PDF | PowerPoint |
| --- | --- | --- | --- |
| 글꼴 | 설치된 Pretendard | 파일에 담긴 Pretendard | Pretendard 대신 다른 글꼴로 보임. 글자 폭이 넓어짐 |
| 긴 문장 줄바꿈 기준 | 글자 단위 | 낱말 단위 | 낱말 단위 |
| 긴 문장 줄 수 | 4줄 | 4줄 | 4줄 |
| 제목 영역에서 다른 픽셀 | 기준 | 첫째 5.3%, 둘째 0.9% | 첫째 23.4%, 둘째 5.2% |
| 본문 영역에서 다른 픽셀 | 기준 | 첫째 0.7%, 둘째 7.2% | 첫째 4.8%, 둘째 10.8% |

둘째 슬라이드의 긴 문장이 나뉜 자리는 다음과 같다.

| 줄 | 기준 화면 | PDF | PowerPoint |
| --- | --- | --- | --- |
| 1 | 각자 작업한 내 | 각자 작업한 | 각자 |
| 2 | 쓴다고 답했 | 쓴다고 | 가장 많은 |
| 3 | 두 번째 어려움 | 두 번째 | 확인하기 |
| 4 | 으로 꼽았습니다. | 어려움으로 꼽았습니다. | 어렵다는 점을 두 번째 어려움으로 꼽았습니다. |

각 칸은 그 줄의 마지막 부분이다. 기준 화면은 낱말 중간에서 줄이 바뀌고 PDF와 PowerPoint는 띄어쓰기에서 바뀐다. PowerPoint는 글꼴이 바뀌어 한 줄에 들어가는 글자 수도 다르다.

### 확인하지 않은 것

- PPTX를 PowerPoint에서 직접 열어 글상자를 고치고 다시 저장하는 것. 이번 비교는 백엔드가 남긴 그림만 썼다
- 출처 연결 정보가 파일에 들어가는지. 백엔드 실험 기록에 따르면 들어가지 않고 출처 문구만 일반 글자로 보인다
- macOS 훑어보기 결과와의 비교, Windows용 PowerPoint와 다른 PDF 뷰어에서의 모습

## 이후 내보내기 단계로 넘기는 제한

- 한글 줄바꿈 기준이 화면은 글자 단위, PDF와 PowerPoint는 낱말 단위다. 편집 화면과 출력이 같은 기준을 쓰도록 계약에서 정해야 한다. 정해지면 슬라이드 렌더러의 줄바꿈 설정을 그에 맞춘다
- PPTX는 글꼴을 파일에 담지 않아 보는 컴퓨터에 글꼴이 없으면 다른 글꼴로 바뀌고 줄바꿈과 제목 너비가 달라진다. 쓸 수 있는 글꼴과 대체 정책이 필요하다
- 화면도 웹폰트를 넣지 않아 글꼴이 설치되지 않은 컴퓨터에서는 대체 글꼴로 보인다. 기준 이미지는 Pretendard가 설치된 환경에서 만든 것이다
- 출처 연결 정보를 파일에 표시하는 방식이 정해지지 않았다
- 위 차이가 정리되기 전에는 PPTX와 PDF를 모두 지원한다고 적지 않는다. 백엔드 실험 기록도 같은 판단이다
