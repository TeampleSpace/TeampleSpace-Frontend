# 프론트엔드 기반 작업 완료 기록

개발 순서의 첫 단계에서 프론트엔드가 맡은 일의 상태를 구현 완료, 자동 검증 완료, 사람의 확인 대기로 나눠 적는다. 기준일은 2026-11-18이다.

## 범위

- 포함: 개발 환경과 CI, 공통 화면 기반, API와 문서 계약 연결 기반, 최소 편집 실험, 파일 출력 비교 기준
- 제외: 배포. 호스팅 연결, 운영 환경 설정, 실제 배포는 아직 진행하지 않기로 해서 이번 종료 조건에 넣지 않는다
- 제외: 실제 인증 화면, 운영 편집기, 내보내기 서비스 같은 이후 단계의 기능

## 자동 검증 결과

2026-11-18, macOS, Node 24.20.0 기준이다. 수정된 디자인 반영, 편집 실험 재검증, 백엔드의 계약 기준 정리 반영까지 모두 합친 상태에서 실행했다.

| 검사 | 결과 |
| --- | --- |
| `npm run lint` | 통과 |
| `npm test` | 테스트 파일 7개 56건 통과. 계약 예제 38개 검사와 편집 관련 27건 포함 |
| `npm run build` | 통과. 운영 빌드에 개발 화면, 모킹, 계약 예제가 들어가지 않음 |
| `npm run contracts:check` | 통과. 백엔드 `main` 3ef0ee2의 계약과 같음 |
| 브라우저 | 합친 상태에서 공통 UI 확인, 편집 실험, 파일 출력 비교 기준 화면이 열리고 한 세션의 저장이 다른 세션에 보이는 것을 확인 |

모든 편집 검증은 모킹 서버 기준이다. 모킹으로 통과한 시험은 프론트엔드가 계약과 일치한다는 뜻이고 실제 서버의 동작을 보증하지 않는다.

각 PR은 CI 통과를 확인한 뒤 요청에 따라 별도의 사람 리뷰 없이 머지했다.

## 사람의 확인이 남은 것

아래가 끝나기 전에는 이 단계 전체를 검증 완료로 적지 않는다.

- 사용자가 한글 입력이 가능하다고 확인했다. 세부 입력기 환경과 조합 및 지연 시나리오별 결과는 별도로 보고되지 않았으며 `docs/editor-experiment.md`에 구분해 기록했다

## 이후 단계로 넘기는 연결 과제

- 실제 서버 연동. 편집에 쓰는 `/v1` 경로가 백엔드에 아직 없어 요청과 응답 전부를 모킹으로만 확인했다. 요소 수정, 편집 화면 스냅샷, 이벤트 스트림, 세션 쿠키와 CSRF 검증, 같은 사이트 프록시 구성을 실제 서버로 확인해야 한다
- 계약에서 아직 정해지지 않은 항목. CSRF 헤더 이름, 이벤트 누락 판단, 다시 연결하는 순서, 묶음 종료 주체는 백엔드 계약의 기준으로 정해져 반영했다. 글꼴과 한글 줄바꿈 같은 사용자 결정 항목과 편집 세션 식별처럼 이후 단계에서 정할 항목이 `docs/contract-notes.md`에 있다
- 한글 줄바꿈 기준과 글꼴. 화면은 글자 단위, PDF와 PowerPoint는 낱말 단위로 줄을 바꾸고 PowerPoint는 글꼴이 바뀐다. `docs/output-comparison.md`에 있다
- Safari와 Firefox, 화면 읽기 프로그램, 200% 확대에서의 확인
- 웹폰트 파일 제공. 지금은 글꼴이 설치된 컴퓨터에서만 문서에 적힌 글꼴로 보인다
