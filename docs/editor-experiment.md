# 편집 실험 기록

개발용 화면 `/dev/editor`에서 공유 문서 예제로 한글 입력과 저장 흐름의 위험을 미리 확인한 기록이다. 완성된 편집기가 아니며 모든 확인은 모킹 서버로 했다.

## 구성

- 화면은 세션 A와 세션 B가 같은 모킹 서버에 붙어 같은 문서를 편집한다. 응답 지연, 응답 유실, 이벤트 중복, 서버 연결 끊김, 이벤트 연결 끊김을 스위치로 만든다
- 코드는 `src/features/editor`에 있다. `session.ts`가 서버 확인본과 미전송 입력을 따로 들고 저장 큐, 이력 묶음, 이벤트 반영, 재연결을 처리한다. `sse.ts`는 이벤트 스트림을 읽고 `coords.ts`는 화면과 문서 좌표를 변환하며 `SlideRenderer.tsx`는 문서를 그리기만 한다
- 텍스트와 이미지는 DOM, 도형은 SVG로 그린다. 확대는 화면 배율만 바꾸고 문서에는 캔버스 단위 좌표만 저장한다
- 미전송 입력은 현재 탭 메모리에만 둔다. IndexedDB와 오프라인 편집은 만들지 않았다

## 저장 흐름의 규칙

- 입력하면 화면용 초안만 바뀌고 서버 확인본은 그대로 둔다
- 텍스트는 마지막 입력 뒤 600ms가 지나면 저장한다. 한글 조합 중에는 저장을 예약하지 않고 조합이 끝난 입력부터 시간을 센다
- 같은 요소는 한 번에 한 요청만 보낸다. 저장 중에 생긴 입력은 다음 요청으로 남기고, 이전 응답은 그 요청에 담긴 입력까지만 확인 처리한다
- 응답을 받지 못했거나 제한 시간을 넘기면 같은 멱등 키, 같은 변경 식별자, 같은 본문으로 다시 보낸다. 새 키는 실제 다음 편집에서만 만든다
- 처리 중이라는 응답을 받으면 서버가 알려 준 시간 뒤에 같은 요청을 다시 보낸다
- 버전 충돌은 자동으로 다시 보내지 않는다. 서버 최신 내용과 내 입력을 함께 보여 주고 사용자가 고른다
- 600ms 저장과 검토 이력 묶음은 따로 센다. 연속 저장은 같은 묶음 식별자를 쓰고 2초 무입력, 30초 경과, 편집 종료, 선택 이동 때 묶음을 닫는다
- 이벤트는 식별자로 중복을 거르고 같은 요소의 오래된 버전은 무시한다. 내 저장이 응답보다 이벤트로 먼저 오면 그것으로 확인 처리한다
- 연결이 끊기면 새 편집을 막고 입력은 그대로 둔다. 다시 연결되면 확인되지 않은 요청은 같은 키로, 남은 입력은 새 요청으로 보낸다

## 자동 시험

2026-11-18, macOS, Node 24.20.0에서 `npm test`로 실행했고 편집 관련 25건을 포함해 46건이 통과했다. 모두 모킹 서버 기준이다.

- 시작하면 스냅샷으로 문서를 읽고 스냅샷의 커서 뒤에서 이벤트 연결을 연다
- 입력이 이어지는 동안은 보내지 않고 600ms 쉬면 한 번 저장한다
- 한글 조합 중에는 5초를 멈춰도 저장하지 않고 조합이 끝난 글자만 한 번 저장한다
- 저장 중에 새 입력이 생기면 이전 응답이 화면을 덮지 않고, 다음 요청은 응답으로 받은 버전을 기준으로 새 키를 쓴다
- 응답을 잃으면 같은 키, 같은 식별자, 같은 본문으로 다시 보내고 서버에는 한 번만 반영된다
- 응답을 잃어도 내 저장의 이벤트가 먼저 오면 그것으로 확인 처리하고 다시 보내지 않는다
- 요청이 서버에 닿지 못했을 때도 같은 요청으로 다시 보낸다
- 처리 중이라는 응답을 받으면 1초 뒤 같은 요청을 다시 보낸다
- 다른 사람이 먼저 저장했으면 덮어쓰지 않고 두 내용을 함께 남기며 10초가 지나도 자동으로 다시 보내지 않는다
- 충돌에서 내 입력으로 다시 편집을 골라도 바로 강제 저장하지 않고, 다시 입력하면 최신 버전을 기준으로 저장한다
- 충돌에서 최신 내용으로 계속을 고르면 내 입력을 버린다
- 입력 중인 요소에 다른 사람의 변경이 오면 보내기 전에 충돌로 표시한다
- 두 세션이 서로 다른 요소를 고치면 충돌 없이 각각 저장되고 서로에게 보인다
- 같은 이벤트가 두 번 와도 한 번만 반영한다
- 연결이 끊기면 새 편집을 막고, 다시 연결되면 마지막 이벤트 뒤부터 재생받는다
- 끊기기 전 입력은 남아 있다가 다시 연결되면 스냅샷, 이벤트 연결, 저장 순서로 처리된다
- 커서가 보관 범위를 벗어나면 스냅샷을 다시 읽어 맞춘다
- 다섯 번 저장해도 검토 이력은 하나이고 2초 쉬면 한 번 닫히며 닫힌 뒤의 입력은 새 묶음이 된다
- 30초 넘게 이어 쓰면 묶음을 닫고 새 묶음으로 이어 간다
- 편집을 끝내면 남은 입력을 바로 저장하면서 묶음을 닫는다
- 이벤트 스트림 조각이 중간에서 잘려 와도 메시지를 온전히 만든다
- 화면 위치와 배율이 달라도 같은 문서 좌표가 나온다

## 브라우저에서 직접 확인한 것

2026-11-18, 앱 내장 브라우저, 화면 1440x900, 모킹 서버 기준이다.

| 항목 | 절차 | 결과 |
| --- | --- | --- |
| 예제 표시 | `/dev/editor` 열기 | 한글 제목과 본문, 줄바꿈, 사각형과 타원, 이미지, 출처가 두 세션에 같게 표시됨 |
| 한글 조합 | 세션 A 본문에서 조합 시작 뒤 ㅎ, 하, 한을 2.9초에 걸쳐 입력하고 조합 종료 | 조합 중 저장 요청 0건, 세션 B는 이전 내용 유지. 조합 종료 뒤 저장 1건, 세션 B에 완성된 글자 표시 |
| 한글 문장 입력 | 같은 입력창에 한글 문장을 이어서 입력 | 내용 저장 1건, 글자 잘림과 중복 없음, 세션 B에 같은 문장 표시 |
| 편집 종료 | Esc | 입력창이 닫히고 묶음 종료 요청 1건 |
| 확대와 좌표 | 배율 150%에서 제목을 화면 기준 72x36px 끌기 | 문서 좌표가 (96, 64)에서 (144, 88)로 바뀜. 화면 이동 거리를 배율로 나눈 값과 일치하고 세션 B도 같은 좌표 |
| 버전 충돌 | 응답 지연 3초로 세션 A가 저장을 보낸 사이 세션 B가 같은 요소를 먼저 저장 | 세션 A에 충돌 표시, 서버 내용은 세션 B의 것 그대로, 세션 A 화면에는 두 내용이 함께 표시됨 |
| 충돌 해결 | 내 입력으로 다시 편집 선택 | 입력창이 내 입력으로 다시 열리고 1.5초 동안 저장 요청 없음. 고쳐 쓰고 나오면 최신 버전을 기준으로 저장되어 세션 B에 표시 |
| 응답 유실 | 다음 저장 응답 버리기를 켜고 저장 | 서버 문서 버전이 한 번만 오르고 저장됨으로 표시 |
| 서버 연결 끊김 | 세션 A가 제목을 입력하는 중에 연결 끊기 | 두 세션 모두 연결 끊김 표시, 입력창은 읽기 전용이 되고 내용 유지, 서버 버전 변화 없음. 다시 연결하면 약 1.8초 뒤 저장되어 세션 B에 표시 |
| 이벤트 연결만 끊김 | 이벤트 연결만 끊기 | 잠시 연결 끊김 표시 뒤 복구. 스냅샷을 다시 읽지 않음 |
| 좁은 화면 | 너비 375px | 가로 넘침 없음, 캔버스가 영역 너비에 맞게 줄어듦 |

한글 조합 항목은 조합 시작과 종료 이벤트를 스크립트로 발생시켜 확인했다.

## 확인하지 못한 것

| 항목 | 이유 | 필요한 선행 작업 |
| --- | --- | --- |
| 실제 한글 입력기로 사람이 타이핑하는 조합 입력 | 자동 조작으로는 입력기를 거칠 수 없음 | `/dev/editor`에서 직접 입력해 글자 잘림과 중복 저장이 없는지 확인 |
| Safari, Firefox | 내장 브라우저 한 종류로만 확인 | 두 브라우저에서 같은 절차 반복. 조합 종료와 입력 이벤트 순서가 브라우저마다 다름 |
| 실제 서버 연동 | 백엔드에 `/v1` API가 없음 | 요소 수정, 편집 화면 스냅샷, 이벤트 스트림 API와 세션 쿠키, CSRF 구성 |
| 서로 다른 브라우저 창이나 기기의 두 세션 | 서버가 없어 한 화면 안의 두 세션으로 대신함 | 실제 서버 연동 뒤 독립된 브라우저 세션으로 반복 |
| 요소가 많은 문서의 입력 반응 속도 | 예제 문서는 요소 7개 | 큰 예제 문서 준비 뒤 측정 |

## 이번 범위에서 만들지 않은 것

- 요소 추가와 삭제, 슬라이드 추가와 순서 변경, 크기 조절
- 탭을 닫기 전 미저장 경고와 발표, 내보내기 전 저장 확인
- IndexedDB, 오프라인 편집, 탭 종료 뒤 초안 복구, 서버에 저장된 내용의 되돌리기
