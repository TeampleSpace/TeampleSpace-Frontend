# 인증과 계정 화면

## 구현 범위

- 로그인 상태와 기능 지원 정보를 서버에서 읽고 인증이 필요한 경로를 보호한다
- 이메일 코드 요청, 검증, 만료 표시, 재전송 대기, 이메일 변경을 제공한다
- 소셜 로그인은 서버의 제공자 인증 시작 경로로 이동한다. 준비되지 않은 제공자는 비활성으로 표시한다
- 이름과 필수 약관의 실제 버전을 저장한다. 약관 주소나 버전이 없으면 가입을 끝낼 수 없다
- 로그인 후 안전한 내부 경로로 돌아간다. 초대 참여는 로그인만으로 실행하지 않는다
- 계정 이름 변경, 로그인 수단 표시, 로그아웃과 탈퇴를 제공한다
- 탈퇴는 소유 프로젝트가 없어야 하며 이메일 코드 또는 연결된 소셜 제공자로 본인 확인을 거친다
- 소셜 재인증 증명은 URL fragment에서 한 번 읽고 주소에서 지운다. 로컬 저장소에 저장하지 않는다
- 저장하지 않은 이름이 있으면 화면 이동과 새로고침 전에 확인한다

## 디자인

피그마의 로그인, 첫 가입, 내 계정 화면을 확인했다. 기존 공통 입력창, 버튼, 모달, 색상과 간격 변수를 사용한다
소셜 제공자 로고와 탐색기 아이콘은 피그마가 제공한 파일을 저장소의 정적 파일로 내려받았다

## 검증

2026-11-18, Node 24.20.0

- 린트 통과
- 빌드 통과
- 테스트 64건 통과
- 추가 테스트에서 내부 복귀 경로 제한, 필수 약관 누락, 로그인과 로그아웃 뒤 CSRF 토큰 교체, 잘못된 인증 코드 응답을 확인했다

자동 테스트의 서버 응답은 모킹이다. 실제 서버와 메일 전달, 소셜 제공자의 왕복 결과는 별도 통합 기록에 남긴다
실제 소셜 제공자 계정과 운영 약관 설정을 대신해서 완료한 것으로 기록하지 않는다

## 실행

백엔드와 같은 사이트 경로로 연결하려면 개발 서버 실행 시 API 프록시를 지정한다

```bash
API_PROXY_TARGET=http://localhost:8081 npm run dev -- --port 5174
```

서버의 허용 프론트 주소도 같은 주소로 설정한다
