## 디자인과 모션

피그마 E52wnXCW6g2Y1rwcvg4DAQ의 자료 목록과 상세, 자료 추가, 원문 및 전체 보기 화면을 직접 읽고 스크린샷과 속성을 비교했다
원문 모달 너비 960px, 패딩 32px, 간격 24px와 모서리 16px를 적용했다
자료 추가는 너비 760px이며 PDF 640px, 링크 584px, 메모 760px로 화면별 최소 높이를 둔다
원문 팝업은 최소 높이 720px이며 PDF 영역은 내부 스크롤과 전체 보기를 제공한다
1440x900에서 원문은 실제 측정 960x722px였다. PDF 영역을 2px 줄여 목표 높이에 맞췄으며 이 마지막 2px 변경의 브라우저 재측정은 제어 연결 해제로 남았다
390x844에서 문서 폭 390px와 모달 폭 356px를 확인했고 가로 넘침이 없었다
모바일 마크다운 모달의 취소와 제출 버튼은 화면 안에 표시됐다

공통 120ms, 180ms, 220ms 모션 토큰을 사용한다
자료 페이지와 주요 콘텐츠, 메뉴, 미리보기 및 충돌 안내에 짧은 등장 효과를 적용하고 모달은 기존 배경과 크기 전환을 유지한다
reduced-motion 공통 규칙과 native dialog의 키보드 및 포커스 동작을 유지한다
추가 애니메이션 라이브러리는 없다

## 검증 결과

### 자동 검사와 모킹

- npm run lint 통과
- npm test 통과, 20개 파일의 142개 검사
- npm run build 통과, PDF.js와 Markdown은 별도 묶음으로 지연 로딩
- BACKEND_DIR=../stage2-backend npm run contracts:check 통과
- 계약 기준은 contracts-source.json에 기록한 백엔드 커밋 421d6b6f2c1bb86147a2a2953b99f59c9ecafe61
- 브라우저 DOM 테스트는 자료 모킹 서버와 PDF 렌더링 대역을 사용하며 실제 분석 검증으로 세지 않는다
- 응답 유실, 중복 요청, 버전 충돌, 권한 회수, 두 번째 목록 페이지의 처리 완료, 외부 삭제, 뒤로가기 입력 보호, 재시도 대기, PDF 재발급과 반복 실패를 포함한다

### 실제 서버와 브라우저

프론트 5181은 8085의 기존 백엔드 구현 c926d75에 연결한다
테스트용 QA 계정과 프로젝트를 사용했고 DB나 기존 사용자 자료를 초기화하지 않았다

- 로컬 이메일 코드 로그인 후 프로젝트 자료 화면 진입
- 실제 presentation.pdf 업로드, 처리 중 표시, 분석 완료와 새로고침 후 재조회
- 실제 https://example.com/ 수집과 원문 본문 조회, 새로고침 후 재조회
- 마크다운 작성과 미리보기, 미저장 닫기 확인, 등록과 재조회, 내용 수정 후 개정 증가
- 팀 메모 초안을 유지한 채 PDF 원문과 전체 보기 진입, 2쪽에서 돌아와 쪽수와 초안 유지, 저장 후 재조회
- 최신 공통 모달에서 Esc를 누르면 전체 보기, 원문, 자료 상세 순서로 복귀하고 각 호출 버튼으로 포커스 복귀
- 존재하지 않는 도메인으로 실제 링크 실패를 만든 뒤 재시도, 분석 취소, 주소와 제목 유지 확인
- 검색 결과 없음, 1440x900과 390x844 화면, 가로 넘침과 모바일 버튼 접근성 확인
- 백엔드 실제 HTTP 검증 32개 통과. 원본 파일 일치, 부분 다운로드, 중복 요청, 메모 충돌, 권한 거부, 제거된 팀원의 원문 주소 및 메모 접근 거절 포함

메일은 로컬 SMTP 수신기다. 외부 메일함이나 소셜 제공자의 실제 왕복 검증은 아니다
최신 백엔드 수정은 실행 환경의 Java DB 연결 제한 때문에 이 로컬 서버에 반영하지 못했다
최신 작업 큐와 PDF 정리 및 링크 연결 제한은 GitHub Actions의 MySQL 8.4 통합 테스트로 검증한다
