# 계약 연결 기반 기록

프론트엔드가 서버 계약을 어떻게 쓰는지, 아직 합의되지 않은 항목이 무엇인지, 무엇을 어떤 방법으로 확인했는지 남기는 문서다.

## 기준

- 제품 범위와 공통 규칙은 노션의 1차 출시 기준과 개발 순서를 따른다. 2026-11-18에 읽었다
- 요청, 응답, 문서 형식은 백엔드 저장소의 공통 계약을 그대로 쓴다. 프론트엔드에서 형식이나 오류 코드를 따로 만들지 않는다

## 계약 폴더

`contracts` 폴더는 백엔드 저장소 `contracts` 폴더의 복사본이다. 직접 고치지 않는다.

| 항목 | 값 |
| --- | --- |
| 복사한 저장소 | TeampleSpace/TeampleSpace-Backend |
| 복사한 커밋 | b0c40dc, 2026-11-18 |
| 복사한 날 | 2026-11-18 |

계약이 바뀌면 폴더를 통째로 다시 복사하고 위 표를 고친 뒤 `npm test`를 돌린다. 어긋난 곳은 `src/shared/api/contracts.test.ts`가 알려 준다.

## 프론트엔드에서 계약을 쓰는 방식

- 화면 코드가 쓰는 형식은 `src/shared/api/contract.ts`와 `src/entities/presentation/schema.ts`에 있다. 계약 스키마를 옮긴 것이고 응답을 받을 때 이 형식으로 검사한다
- 예제 문서와 편집 화면 스냅샷은 계약의 예제 파일을 그대로 쓴다. 백엔드의 파일 출력 실험과 같은 문서다
- 서버가 준비되기 전에는 `src/mocks/server.ts`의 모킹 서버로 확인한다

`src/shared/api/contracts.test.ts`가 세 가지를 확인한다.

- 계약의 예제 목록 전체가 스키마 검사에서 기대한 통과 여부와 일치한다. 백엔드 테스트와 같은 검사다
- 프론트엔드 형식이 계약의 올바른 예제를 모두 받아들인다
- 모킹 서버의 응답과 이벤트, 편집 세션이 보내는 요청이 계약 스키마를 통과한다

## 아직 합의되지 않은 항목

백엔드가 제안으로 채워 둔 항목은 `contracts/README.md`의 합의가 필요한 항목에 있다. 캔버스 단위와 크기, 텍스트 스타일 범위, 도형 종류, 이미지 자르기 표현, 수정 요청의 교체 방식, 이벤트 식별자 형식, 세션 초기 정보와 스냅샷의 항목 이름이 여기에 들어 있다. 프론트엔드는 지금 이 제안을 그대로 따른다.

아래는 프론트엔드 작업 중에 나온 항목으로 계약에 아직 없다.

| 항목 | 프론트엔드의 현재 처리 | 위치 |
| --- | --- | --- |
| CSRF 토큰을 싣는 요청 헤더 이름 | `X-CSRF-Token`으로 임시 지정 | `src/shared/api/contract.ts` |
| 이벤트를 놓쳤는지 판단하는 기준 | 이벤트 식별자는 해석하지 않으므로 이벤트의 `presentationVersion`이 직전보다 2 이상 크면 놓친 것으로 보고 스냅샷을 다시 읽음. 문서 버전을 올리는 모든 이벤트가 이 값을 싣는지 확인 필요 | `src/features/editor/session.ts` |
| 다시 연결할 때의 순서 | 보낼 입력이 없으면 마지막 이벤트 뒤부터 재생만 받고, 보낼 입력이 있으면 스냅샷을 먼저 읽어 비교한 뒤 보냄. 항상 스냅샷부터 읽어야 하는지 확인 필요 | `src/features/editor/session.ts` |
| 편집 묶음을 닫는 주체 | 클라이언트가 2초 무입력, 30초 경과, 편집 종료 때 종료 요청을 보냄. 서버도 같은 기준으로 닫으므로 시각 차이로 `EDIT_GROUP_CLOSED`를 받으면 새 묶음으로 다시 보냄. 클라이언트가 종료 요청을 보내야 하는지 확인 필요 | `src/features/editor/session.ts` |
| 내용 없이 묶음만 닫는 요청의 버전 검사 | 모킹은 요소 버전을 검사하지 않고 현재 요소를 그대로 돌려줌 | `src/mocks/server.ts` |
| 이미 닫힌 묶음에 종료만 요청했을 때 | 모킹은 `EDIT_GROUP_CLOSED`로 응답하고 프론트엔드는 이미 닫힌 것으로 보고 넘어감 | `src/mocks/server.ts` |
| 버전 충돌 때 서버 최신 내용을 얻는 방법 | 충돌 응답에는 현재 버전만 있어 이벤트로 받은 내용이나 스냅샷 재조회로 얻음 | `src/features/editor/session.ts` |
| 슬라이드에서 쓰는 글꼴의 웹폰트 제공 | 예제는 Pretendard를 쓰지만 웹폰트 파일이 없어 화면은 시스템 글꼴로 표시됨 | `src/shared/styles/tokens.css` |

## 모킹과 실제 연동의 구분

2026-11-18 기준 백엔드에는 계약 형식과 요소 수정 처리의 일부가 있지만 프론트엔드가 호출할 수 있는 `/v1` 경로는 아직 열려 있지 않다. 그래서 실제 서버 연동은 한 건도 확인하지 못했다.

모킹 서버는 계약의 저장, 멱등, 이력 묶음, 이벤트 규칙을 메모리에서 흉내 낸다. 모킹으로 통과한 시험은 프론트엔드 코드가 계약과 일치한다는 뜻이다. 실제 서버의 동작을 보증하지 않는다.
