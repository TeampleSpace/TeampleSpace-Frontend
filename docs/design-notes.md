## 자료끼리 서로 다른 부분

제품 화면을 따랐다. 버튼과 간결한 모달은 같은 날 수정된 디자인 시스템과 제품 화면을 다시 확인해 반영했다.

| 항목 | 한쪽 | 다른 쪽 | 따른 것 |
| --- | --- | --- | --- |
| 주요 버튼 높이 | 프론트엔드 설계서 48px | 피그마 화면 44px | 피그마 화면 |
| 페이지 제목 줄높이 | 프론트엔드 설계서 40px | 피그마 화면 38px | 피그마 화면 |
| 입력창 | 피그마 입력 컴포넌트는 회색 면, 테두리 없음, 모서리 12px, 값 16/24 | 피그마 화면은 흰 면, 테두리 #7F8997, 모서리 8px, 값 16/26 | 피그마 화면 |
| 모달 배경 농도 | 프로젝트 생성 모달 36% | 삭제 확인과 안내 모달 32% | 32% |

입력창의 #7F8997 테두리와 기존 가운데 빈 상태 안내는 유지한다. 공통 UI 확인 화면의 영역은 외곽 카드 대신 제목, 여백, 구분선으로 나눈다.

## 추가로 확인해 반영한 것

- 프로젝트 삭제 모달의 이름 입력창은 피그마에 맞춰 56px 높이의 여러 줄 입력으로 바꿨다. 여백 16px, 글자 14/22, 테두리 #7F8997이다
- 내보내기 진행 모달은 제목, 설명, 회색 상태 줄, 닫기 버튼으로 구성했다. 공통 UI 확인 화면에서 열 수 있다

### 확인 모달의 기준

이전 기록은 확인 모달의 틀이 사용 기준 화면과 제품 화면에서 서로 다르고 너비 560px의 근거를 찾지 못했다고 적었다. 2026-11-18에 제품 화면 세 개를 다시 읽어 보니 제품 화면 안에 틀이 두 가지 있었다.

| 항목 | 요청 제한과 일시 오류 안내 219:7716 | 프로젝트 삭제 확인 219:6669, 내보내기 진행 219:7455 |
| --- | --- | --- |
| 너비 | 560px | 640px |
| 안쪽 여백 | 24px | 32px |
| 모서리 | 12px | 16px |
| 요소 간격 | 16px | 24px |
| 버튼 간격 | 8px | 12px |
| 버튼 위 여백 | 8px | 없음 |
| 버튼 세로 맞춤 | 가운데 | 위쪽 |

너비 560px는 안내 모달의 값이었다. 사용 기준 화면 227:1612가 적은 모서리 12px와 여백 24px도 이 안내 모달과 같다.

기준은 제품 화면이다. 화면마다 그 화면의 틀을 그대로 따른다. 사용 기준 화면에는 너비와 간격이 없어 구현 기준으로 쓸 수 없고, 제품 화면은 값이 모두 있으며 실제로 만들 화면이기 때문이다. 그래서 공통 모달의 크기를 세 가지로 나눴다.

| 크기 | 쓰는 곳 | 너비 | 여백 | 모서리 | 요소 간격 | 버튼 간격 |
| --- | --- | --- | --- | --- | --- | --- |
| `dialog` | 짧은 안내 | 560px | 24px | 12px | 16px | 8px |
| `confirm` | 확인과 진행 | 640px | 32px | 16px | 24px | 12px |
| `form` | 입력이 여러 개인 모달 | 760px | 32px | 16px | 24px | 12px |

이 선택은 구현하면서 정한 것이다. 확인 모달도 560px 틀로 통일하려면 공통 UI 확인 화면의 두 모달에서 크기 지정만 빼면 된다.

사용 기준 화면의 텍스트 동작 예시는 SemiBold 15/22인데 버튼 컴포넌트와 제품 화면의 닫기는 Medium 14/20이다. 구현은 Medium 14/20이다.

브라우저에서 확인한 동작은 다음과 같다. 2026-11-18, 화면 1440x900과 너비 320px 기준이다.

- 버튼 높이는 주요와 삭제 44px, 보조와 텍스트 40px이다
- 오류 안내는 너비 560px, 높이 142px이고 상세 정보를 누르면 요청 번호가 펼쳐지며 버튼의 펼침 상태가 함께 바뀐다
- 확인 모달을 열면 취소 버튼에 포커스가 놓이고, 닫으면 모달을 연 버튼으로 포커스가 돌아온다
- 여러 줄 입력창은 높이 56px이고 이름표와 연결되어 있다
- 너비 320px에서 화면과 모달에 가로 넘침이 없다

확인 모달의 크기를 나눈 뒤 같은 날 앱 내장 브라우저에서 다시 쟀다.

- 삭제 확인과 내보내기 진행 모달은 너비 640px, 여백 32px, 모서리 16px, 요소 간격 24px, 버튼 간격 12px, 버튼 위 여백 0이다
- 안내 모달은 너비 560px, 여백 24px, 모서리 12px, 요소 간격 16px, 버튼 간격 8px 그대로이고 입력 모달은 760px 그대로다. 오류 안내의 너비 560px도 그대로다
- 삭제 확인 모달을 열면 취소 버튼에 포커스가 놓이고 Tab을 눌러도 포커스가 모달 안에 머문다. Esc로 닫으면 모달을 연 버튼으로 포커스가 돌아온다
- 너비 320px에서 삭제 확인 모달의 너비는 286px이고 화면과 모달에 가로 넘침이 없다

## 피그마에서 확인하지 못한 것

- 일반 문서 조회의 로딩 표시. 내보내기 진행 모달은 별도 화면으로 확인했다
- 삭제 버튼의 올림과 누름 상태
- 프로젝트 탐색기가 있는 화면 틀과 아이콘. 다음 단계에서 만든다

편집 실험 화면과 파일 출력 비교 기준 화면은 개발용이라 피그마 화면을 따르지 않았다. 실제 편집 화면은 이후 단계에서 피그마를 기준으로 만든다.

## 진행 중인 제출 버튼 확인

공통 버튼을 폼의 제출 버튼으로 쓸 때 진행 중에는 클릭 처리와 폼의 기본 제출을 함께 막는다. 비활성 속성 대신 클릭의 기본 동작을 막아서 진행 중에도 버튼의 포커스가 유지된다.

2026-11-18에 앱 내장 브라우저에서 공통 UI 확인 화면의 폼 제출 예시로 확인했다. 제출하면 3초 동안 진행 중이 되는 폼이고 마우스 클릭과 키 입력은 브라우저 도구로 실제 입력을 보냈다.

| 절차 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 제출 버튼을 누른 뒤 진행 중에 다시 누르고 버튼에서 Enter를 누름 | 폼 제출 3회, 클릭 처리 1회 | 폼 제출 1회, 클릭 처리 1회 |
| 진행 중에 버튼에서 스페이스를 누름 | 확인하지 않음 | 횟수 변화 없음. 포커스는 버튼에 남음 |
| 진행 중에 입력란에서 Enter를 누름 | 확인하지 않음 | 횟수 변화 없음 |
| 진행이 끝난 뒤 버튼을 한 번 누름 | 확인하지 않음 | 폼 제출과 클릭 처리가 한 번씩 늘어남 |
| 진행 중이 아닐 때 입력란에서 Enter를 누름 | 확인하지 않음 | 폼 제출과 클릭 처리가 한 번씩 늘어남 |

자동 테스트는 더하지 않았다. 이 저장소의 테스트는 브라우저 환경 없이 돌기 때문에 폼 제출을 흉내 낼 수 없다. 화면 읽기 프로그램과 Safari, Firefox에서는 확인하지 않았다.

자료 관리 메뉴의 펼친 모양은 피그마에 없다. 이름 변경과 삭제를 담은 작은 메뉴로 만들었고 Esc와 바깥 포커스로 닫는다. 분석 실패 상태도 피그마에 화면이 없어 처리 중 화면의 안내 줄과 숨겨진 동작 영역의 배치를 따랐다.
