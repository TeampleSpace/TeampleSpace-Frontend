# 화면 애니메이션

화면 진입과 조작 결과를 짧게 보여 주는 CSS 애니메이션이다. 입력 상태와 라우터, 요청 처리 코드는 바꾸지 않는다.

| 대상 | 움직임 | 시간 |
| --- | --- | --- |
| 공통 버튼 | 배경과 글자색 전환, 누를 때 아래로 1px 이동 | 120ms |
| 소셜 로그인 버튼 | 안쪽 강조선, 누를 때 아래로 1px 이동 | 120ms |
| 탐색 메뉴와 프로젝트 제목 링크 | 배경과 글자색 전환 | 120ms |
| 입력창과 소유자 선택 항목 | 테두리와 배경색 전환 | 120ms |
| 프로젝트 카드, 계정과 설정 본문 | 새로 표시될 때 투명도 전환 | 220ms |
| 모달과 배경 | 모달을 8px 올리며 표시, 배경 투명도 전환 | 180ms |
| 오류 안내와 상세 정보 | 새로 표시될 때 투명도 전환 | 220ms |

공통 시간과 감속 곡선은 `src/shared/styles/tokens.css`에 있다. 화면 전체를 다시 마운트하거나 입력마다 애니메이션을 시작하는 로직을 넣지 않는다. 새로 나타나는 검색 결과 카드는 진입 효과를 재생한다. 인증 화면을 제외한 공통 효과에는 순차 재생이나 추가 대기 시간이 없다.

모달은 열 때만 움직인다. 닫기는 즉시 처리해 포커스 복귀와 다음 조작을 늦추지 않는다. 키보드 포커스의 외곽선도 즉시 표시한다. 비활성 버튼과 진행 중 버튼에는 눌림 이동을 적용하지 않는다.

`prefers-reduced-motion: reduce`에서는 애니메이션과 전환을 끈다. 모달 배경과 의사 요소도 포함한다. 로딩 원은 정지하지만 진행 중 문구와 접근성 상태는 유지한다.

## 인증 화면

로그인, 이름 입력, 인증 결과 화면은 같은 인증 레이아웃을 사용한다. 헤더와 소개 영역, 폼을 구분하고 좁은 화면에서는 세로로 배치한다. 배경, 제목, 밑줄에는 기존 디자인 색상 토큰을 사용한다.

- 헤더, 제목, 소개 문구, 폼을 400ms에서 650ms 동안 순서대로 표시
- 제목의 파란색 변화는 6500ms, 주황색 밑줄은 5800ms, 소개 문구 옆 작은 점은 2800ms 주기로 반복
- 별도 움직임 제어 버튼 없이 장식 효과를 재생
- 동작 줄이기 설정에서는 반복 효과와 진입 효과를 끄고 기본 글자색과 밑줄을 표시
- 이메일 입력 포커스는 기존 외곽선과 옅은 파란색 강조로 표시

### 인증 화면 검증

2026-11-19 로그인 디자인 변경 후 린트, 기존 테스트 92건, 운영 빌드, API 계약 비교를 통과했다.

앱 내장 브라우저에서 움직임 제어 버튼이 없는 것과 제목, 밑줄의 반복 스타일 값이 접속 후에도 달라지는 것을 확인했다. CSS 뷰포트 너비 320px에서 가로 넘침 없이 이메일 입력과 Tab 이동이 가능했다. 입력 확인에 사용한 예시 주소는 제출하지 않았다. 브라우저 오류 로그는 없었다.

리뷰에서 진입 효과가 비활성 소셜 버튼의 불투명도를 덮어쓰는 문제를 확인해 활성 버튼에만 적용하도록 수정했다. 실제 로그인 컴포넌트에 샘플 세션을 전달한 임시 화면에서 카카오와 Google은 비활성, 네이버는 활성으로 구성했다. 진입 효과가 끝난 후 비활성 버튼은 불투명도 0.55와 애니메이션 없음, 활성 버튼은 불투명도 1을 유지했다. Tab 이동도 비활성 카카오를 건너뛰고 네이버에 도달했다. 임시 파일은 검증 후 저장소에서 제거했다.

동작 줄이기 대응은 새 효과가 `prefers-reduced-motion: no-preference` 안에 있고 기존 전역 중지 규칙이 유지되는 것을 코드로 확인했다. 이번 로그인 변경 후 동작 줄이기 에뮬레이션과 실제 모바일 기기 검증은 수행하지 않았다. 이메일 발송, 소셜 로그인 완료 등 실제 인증 서버 연동은 이번 검증 범위에 포함하지 않았다.

## 공통 효과 검증

2026-11-19, Node 24, 앱 내장 브라우저와 Chrome에서 확인했다.

- 린트, 기존 테스트 92건, 운영 빌드, 고정 원본과의 API 계약 비교 통과
- 실제 브라우저의 계산된 스타일에서 버튼 전환 120ms, 모달과 배경 180ms, 로그인과 프로젝트 카드 220ms 확인
- 확인 모달에서 취소에 초기 포커스, Tab 순환, Esc 닫기 후 실행 버튼으로 복귀 확인
- 모달을 닫고 바로 다시 열어도 하나만 열리며 초기 포커스 유지
- 제출 직후 Enter, Space, 입력란 Enter를 이어 눌러도 진행 중 제출 횟수가 늘지 않음
- 오류 상세 정보 펼침과 숨김, 로그인 입력, 프로젝트 검색, 프로젝트 상세와 설정 이동 확인
- 320x640에서 가로 넘침 없음. 긴 모달은 너비 286px, 높이 608px 안에서 본문 스크롤
- 1280x800에서 프로젝트 생성 모달과 입력 포커스 확인
- Chrome 개발자 도구에서 동작 줄이기를 에뮬레이션하면 모달, 배경, 로딩 원의 animation-name이 none, 버튼 transition-duration이 0s인 것을 확인

공통 UI는 `/dev/ui`, 로그인은 `/login`에서 확인했다. 프로젝트 화면은 기존 컴포넌트를 임시 진입 파일에서 샘플 세션과 프로젝트 조회 응답으로 연결했다. 임시 파일은 검증 후 저장소에서 제거했다. 이 검증은 실제 프로젝트 저장이나 외부 소셜 로그인 연동 검증이 아니다.

개발용 지연 로딩 경로에서 기존 HydrateFallback 경고가 있으며 이번 변경의 실행 오류는 없었다. Safari, Firefox와 실제 모바일 기기는 확인하지 않았다.
